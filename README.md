# HIM — He Is Memory

> PROJECT HIM：Minecraft Java Edition 26.3／Paper 伺服器的心理恐怖插件。
> 世界裡有一個會觀察、記憶、跟蹤、干擾，必要時會獵殺你的存在。他不需要一直出現——沉默本身就是他的選擇。

- **只需伺服器插件**：玩家使用原版客戶端即可，不需要模組或資源包。
- **不依賴 ProtocolLib／PacketEvents／NMS**：完全使用 Paper 26.3 公開 API。
- 正式名稱 **HIM**（He Is Memory），呼應本插件的核心：跨登入、跨重啟的持久記憶。

## 需求與安裝

| 項目 | 需求 |
|---|---|
| 伺服器 | Paper **26.3**（開發與測試使用 build 205） |
| Java | **25** 以上（Paper 26.3 官方最低需求） |
| 客戶端 | 原版 Minecraft Java Edition 26.3 |
| 相依插件 | 無 |

1. 將 `HIM-1.0.0.jar` 放入伺服器的 `plugins/` 資料夾。
2. 啟動伺服器，會產生 `plugins/HIM/config.yml`。
3. 依需要調整設定後執行 `/him reload`（設定有錯時會列出**所有**錯誤並保留原設定，不會無聲失敗）。
4. 建議執行一次 `/him selftest`（可在主控台執行）確認伺服器端功能正常，詳見[驗證狀態](#驗證狀態請先讀)。

> `/him selftest` 會建立一個名為 `him_selftest` 的超平坦測試世界，所有測試只在那個世界進行，不會修改遊戲世界。

## 快速開始

```
/him status                 狀態、效能、進行中的事件
/him summon <玩家>          讓 HIM 出現在玩家附近（確認外觀與私人可見性）
/him trigger <事件> <玩家>   立即觸發任一事件（測試用，不會影響記憶與性格）
/him chase <玩家> now        立刻開始一場追殺
/him debug <玩家>           看導演怎麼看待這位玩家：階段、張力、本次行動機率、可用事件
/him stop                   結束一切並移除所有 HIM
```

新玩家一開始處於「未察覺」階段：只會有難以確定的聲音。隨著實際遊玩時間與遭遇累積，HIM 才會現身、跟蹤、干擾，最後才可能追殺（預設約 2 小時遊玩且有數次顯著遭遇後）。

## HIM 如何運作

### 本體：Paper Mannequin
HIM 是一個穿著 Mojang 簽名經典白眼皮膚的 `Mannequin` 實體。它**預設對所有人隱藏**，只透過 `Player#showEntity` 顯示給指定玩家——這就是私人幻覺的實現方式：不相干的玩家客戶端根本不知道這個實體存在。本體沒有重力、沒有 AI、不會被存檔（`persistent=false`），且帶有標記，任何殘留都會在區塊載入時被清除。

### 追殺時的移動
追殺時「HIM 實際所在的位置」是一個虛擬載體：
- 由插件內建的 **A\* 網格尋路**（適用玩家大小的身體：上一格台階、下落三格內、游泳、穿過木門與柵欄門，避開岩漿／火／仙人掌等）規劃路徑；
- 以精確速度沿路徑移動，Mannequin 每 tick 跟隨。

這樣的設計不依賴生物 AI，所以**不受伺服器「實體啟動範圍」影響**（遠離玩家的生物幾乎不運算），也不會在世界中留下隱形生物。這是實機測試後才確定的設計，見 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。

### 恐怖導演（Horror Director）
沒有時間表。每位玩家每隔幾秒評估一次：
1. **危險率**：安靜越久越可能發生（Weibull 分佈），受階段、性格、環境（夜晚、地下、雷雨）、伺服器效能影響。
2. **張力節奏**：事件會累積張力 → 達到高峰（每輪隨機門檻）→ 進入**刻意的長時間沉默**，再重新累積。強度最高的事件（例如追殺）自然出現在累積的尾聲。
3. **全伺服器預算**：權杖桶限制全服總量，人多時不會變成鬼屋。
4. **意圖（Utility AI）**：在 存在感／觀察／跟蹤／干擾／追殺 之間依性格、玩家性情與情境計分選擇。
5. **事件**：依情境適配度、對這位玩家的新鮮度（避免重複）、HIM 學到的偏好加權抽選。
6. **模式與破格**：私人／群體／共享；以及是否刻意打破玩家已熟悉的規律。

模擬 24 小時（最高階段）的結果：平均每小時約 4 個事件、14 種以上不同事件、追殺約每 4 小時一次，且每次高峰後有約 25–30 分鐘的沉默（見 `HorrorDirectorTest`）。

### 記憶與人格
- **每位玩家**：活動熱點（16×16 區塊，會衰減）、由睡覺／開箱子／建造推測的**基地位置**、行為摘要（地下比例、夜間戶外、獨處、建造與挖掘速率）、對目擊的反應（無視／注意／靠近／逃跑／攻擊 → 性情）、追殺紀錄與**慣用逃脫方式**、對規律的熟悉程度、同伴關係、最近 48 次遭遇。
- **世界**：HIM 的性格（好奇、耐心、攻擊性、模仿、孤立偏好、膽量、破格傾向），每個伺服器隨機產生、隨經驗緩慢演化並向基準回歸；特殊地點（逃脫、死亡、被攻擊、登出的地點）；對各事件的偏好。
- **反制**：常從水中逃走的玩家會遇到更會游泳的 HIM；常跑贏的會遇到稍快的 HIM；常躲起來的會被搜得更久；常反擊的需要打更多下。
- **預期與破格**：玩家看過多次「靠近就消失」之後，HIM 有機會這次不消失——轉身離開、走出掩體、在窗外後退到黑暗中、門自己打開。

### 追殺
- 開始方式：從視線外接近，或（破格／由跟蹤升級）直接現身靜止凝視約 2 秒後開始。
- 行為：預測玩家移動方向、短暫爆發衝刺、失去視線後搜尋最後位置與逃跑方向、**假撤退**（轉身消失，在看不見的情況下繞到前方再出現）、開木門並在之後關上、被擊中時硬直。
- **公平逃脫**：持續衝刺（預設 HIM 奔跑 5.0 格／秒，玩家衝刺約 5.6）拉開 40 格以上 3 秒、中斷視線讓搜尋失敗、躲進有光照的室內、擊中他 6 次將他擊退、撐過 100 秒時限。
- **不作弊**：絕不在玩家看得到時瞬移；卡住時最多 2 次「在玩家看不到的情況下」重新定位；仍卡住就放棄並消失。
- 傷害：預設 5（會被遊戲難度縮放：簡單 3.5、普通 5、困難 7.5）、冷卻 1.2 秒；`chase.lethal: false` 時最多讓玩家剩半顆心。

|---|---|---|

| `/him events` | `him.command.status` | 所有事件與其階段、強度、冷卻、模式 |
| `/him personality` | `him.command.status` | HIM 目前的性格與基準值 |
| `/him debug [on\|off]` | `him.command.debug` | 在聊天室接收即時除錯訊息 |
| `/him debug <玩家>` | `him.command.debug` | 導演對該玩家的完整判斷 |
| `/him trigger <事件> <玩家> [private\|group\|shared] [subvert]` | `him.command.trigger` | 立即觸發事件 |
| `/him chase <玩家> [now]` | `him.command.trigger` | 開始追殺 |
| `/him summon <玩家> [shared]` | `him.command.summon` | 召喚 HIM |
| `/him stop [玩家]` | `him.command.summon` | 結束事件並移除 HIM |
| `/him cleanup` | `him.command.summon` | 清除殘留實體與假方塊，世界修改排程還原 |
| `/him memory <玩家>` | `him.command.memory` | 查看記憶（離線玩家也可） |
| `/him memory <玩家> reset` | `him.command.reset` | 清除該玩家的記憶 |
| `/him stage <玩家> <0-4\|auto>` | `him.command.memory` | 固定或恢復自動階段 |
| `/him participation <玩家> <on\|off\|default>` | `him.command.memory` | 個別玩家是否參與 |
| `/him reset world confirm` | `him.command.reset` | HIM 重生並產生新性格 |
| `/him pause` / `/him resume` | `him.command.toggle` | 暫停／恢復（暫停時手動觸發仍可用） |
| `/him reload` | `him.command.reload` | 重新載入設定 |
| `/him selftest` | `him.command.selftest` | 伺服器內自我測試 |

- `him.admin`：以上全部（預設 OP）。
- `him.exempt`：永遠不會成為目標（預設無人擁有）。
- **手動觸發（trigger／chase／summon）不會改變玩家記憶、追殺統計或 HIM 的性格**，測試不會污染遊戲。

## 設定重點

完整、逐項註解的設定檔見 `src/main/resources/config.yml`（安裝後在 `plugins/HIM/config.yml`）。最常調整的：

| 想要… | 調整 |
|---|---|
| 整體更頻繁／更少 | `director.frequency` |
| 更溫和／更激烈 | `director.intensity`、`director.max-stage` |
| 不要追殺 | `chase.enabled: false` 或 `director.max-stage: 2` |
| 追殺不致死 | `chase.lethal: false` |
| 追殺更難逃 | `chase.speed.run`（超過 5.6 會有警告）、`chase.escape-distance` |
| 不修改真實世界 | `world-modification.real-changes: false` |
| 完全不碰方塊 | `world-modification.enabled: false` |
| 只在特定世界 | `worlds.mode: whitelist` + `worlds.list` |
| 某些事件不要 | `director.disabled-events: [false_join, hunt]` |
| 更快進入後期 | `director.stage-play-minutes` / `stage-encounters` |

## 資料與記憶

```
plugins/HIM/data/
├── players/<UUID>.json     每位玩家的記憶（有上限，不保存逐 tick 資料）
├── world-state.json        HIM 的性格、特殊地點、事件偏好、建築區
└── world-changes.json      真實世界修改的回滾日誌
```

- JSON，寫入時先寫暫存檔再原子替換；損毀的檔案會被改名為 `.corrupt-<時間>` 隔離並重新開始，不會覆蓋。
- 讀寫都在獨立 IO 執行緒；序列化在伺服器執行緒完成，IO 執行緒不接觸可變物件。
- 自動存檔（預設 5 分鐘）、玩家離線時存檔、關服時同步等待寫入完成。
- `memory.forget-after-days`（預設 180 天）未上線的玩家資料會被刪除。

## 安全、效能與相容性

**世界安全**
- 假方塊只送給特定客戶端；固體假方塊不會放在玩家 3 格內，玩家靠近或互動時立即還原，事件結束／換世界／關服時全部還原。
- 真實修改只限天然方塊（天然樹葉以「非持久」屬性判斷，玩家放的樹葉不會被動），遠離世界出生點、玩家床位、HIM 推測的基地與玩家大量建造的區塊（預設 48 格），遵守 `mobGriefing`，**先寫入日誌再修改**；到期後只在 40 格內沒有玩家時還原，且只在方塊仍是 HIM 放的狀態時還原（玩家改過就尊重玩家）；關服時立即還原所有已載入區塊中的修改，其餘重啟後繼續處理。
- 唯一會留下的變化是 `door_left_open` 打開的門（只開門，不破壞）；可用 `world-modification.door-interaction: false` 關閉。

**多人協調**
- 每位玩家同時最多參與一個事件（鎖定），群體事件鎖定所有參與者。
- 全服身影上限（預設 3）、追殺上限（預設 1）、全服恐怖預算。
- 玩家離線、死亡、換世界、長距離傳送時，相關事件立即結束並清理；離線發生在遭遇中會被記住，回來時……他在等。

**效能**
- 所有世界存取都在伺服器主執行緒，且**絕不載入區塊**（視線、尋路、找位置遇到未載入區塊一律視為牆）。
- 玩家情境取樣錯開在不同 tick；視線檢查隔 tick 執行；尋路有節點上限（3000）並只在目標明顯移動時重新規劃。
- 效能守衛：伺服器 MSPT ≥ 40 或 HIM 自身超過每 tick 預算時降低頻率並暫停新追殺；MSPT ≥ 48 或 TPS < 17 時結束所有事件，直到恢復（啟動後 90 秒內不採用 TPS 平均值）。
- 實測（本機 Paper 26.3）：HIM 閒置約 0.03 ms/tick；導演一次決策約 1–5 µs。

**相容性**
- 會被其他插件取消的生成（例如區域保護禁止生物生成）會被安全地視為「此處無法發生」。
- 其他生物不會以 HIM 為目標；HIM 的實體不受傷害、不燃燒、不轉化。
- 世界保護插件：真實修改不會詢問 WorldGuard 等插件的區域權限（沒有通用 API）。若伺服器重度依賴區域保護，建議設定 `world-modification.real-changes: false`，或以 `worlds` 黑名單排除。
- `folia-supported: false`：未支援 Folia。

## 驗證狀態（請先讀）

本專案區分四種狀態。**「編譯成功」不等於「恐怖效果在玩家眼中完全正常」。**

**已在真實伺服器與測試客戶端上驗證：**
- 私人可見性：目標客戶端收到 Mannequin，旁邊 4 格內的另一位玩家**完全沒有收到**該實體；共享模式兩人都收到；`/him stop`、玩家離線後實體被移除，世界中無殘留。
- 群體事件的資訊不對稱：`behind_companion` 一人看到 HIM、另一人只收到一個腳步聲；`cave_mining` 群體模式兩人收到來自不同方向的挖掘聲。
- 私人聲音、假加入訊息、假告示牌（方塊與文字）、火把熄滅與還原、方塊裂痕動畫、神龕（31 個假方塊，走近時一次還原）只送給目標。
- 凝視判定使用真實客戶端的視角：遠方身影被盯住約 1 秒後消失；窗外身影在移開視線後消失；探頭者被發現後退回掩體再消失；背後身影在轉身後一瞬消失。
- 追殺：現身、接近、攻擊（含冷卻）、持續逃跑可逃脫、擊中 6 次擊退、玩家中途離線立即清理、死亡依實際傷害來源歸因。
- 真實修改：通道與無葉樹寫入日誌，關服時還原，重啟後確認方塊已復原；保護半徑會拒絕在出生點與推測基地附近修改。
- 導演自然運作：在加速設定下自然觸發 `leafless_tree`、`dread`、`false_join` 等並正確記錄。

## 已知限制與問題

- **測試客戶端的限制**：自動化連線測試使用 26.1 協定的 mineflayer 經 ViaBackwards 轉譯；測試客戶端關閉了物理運算，玩家「移動」以伺服器傳送模擬。這驗證了封包層面的正確性，但不等同原版客戶端的畫面。
- **傷害受難度縮放**：追殺傷害使用 `MOB_ATTACK` 傷害類型，會依難度縮放；和平難度下傷害為 0（追殺仍會發生，但不會造成傷害）。
- **世界保護插件**：見上方相容性說明。
- **對 HIM 開火**：投射物命中會被視為攻擊並取消傷害，但 HIM 不會被真正擊倒；擊退由擊中次數決定。
- **木門以外的門**：追殺尋路不會穿過鐵門與活板門。
- **開闊地形**：完全沒有遮蔽物的地形中，「需要掩體」的事件（探頭、追殺中的隱藏重新定位）會自動不發生或改用其他方式；這是刻意的。
- **Folia 不支援。**

## 從原始碼建置

需要 JDK 25。

```bash
./gradlew build          # 編譯（-Xlint:all -Werror）、執行全部單元測試、產生 JAR
# 產物：build/libs/HIM-1.0.0.jar
```

專案結構：

```
src/main/java/dev/projecthim/him/
├── HimPlugin.java / Him.java    進入點、服務容器與唯一的 tick 迴圈
├── config/      設定檔解析與驗證
├── director/    恐怖導演（純邏輯：危險率、張力、效用 AI、學習）＋ 與伺服器的橋接
├── chase/       追殺大腦（純邏輯狀態機）
├── nav/         A* 網格尋路
├── memory/      記憶模型、JSON 儲存、非同步存取
├── entity/      Mannequin 本體、虛擬載體、實體登錄（防殘留）
├── event/       事件框架、Apparition（身影與玩家反應）、24+1 個事件
├── sense/       視線（玻璃透明、樹葉半透明）、找位置
├── world/       假方塊、真實修改日誌、保護規則
├── player/      玩家工作階段與情境取樣
├── perf/        效能守衛
├── listener/    事件監聽
└── command/     /him 指令與伺服器內自我測試
```
